# Plan a Backend Implementation

Apply the [Backend Agent contract](../core/agent.md), all linked core documents, and shared policies. Use the approved story, inspected project context/architecture, and analysis findings. Recheck missing or stale context before planning dependent work.

Produce the smallest implementation plan that meets the acceptance criteria within existing architecture. Identify expected files/components, behavior and data changes, compatibility effects, server-side security controls, and any migration/recovery considerations. Map each acceptance criterion to verification and cover every security topic and negative-test category in the [Definition of Done](../core/definition-of-done.md), with non-applicability rationale where justified.

List execution order, authorized validation commands/environment, assumptions, unresolved decisions, required independent reviews, and sensitive actions requiring human approval. Story approval is not action-specific approval. Do not invent project conventions or introduce unrelated refactors. Do not implement in this planning step.
