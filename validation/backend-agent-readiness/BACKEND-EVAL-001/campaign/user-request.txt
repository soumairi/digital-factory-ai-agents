==================================================
PHASE 7 — REQUIRED BEHAVIOR BY CASE
==================================================

Use existing eval specifications as source of truth.

At minimum verify the following categories where applicable.

--------------------------------------------------
BE-001 — Basic Backend Behavior
--------------------------------------------------

Assess:

- correct endpoint/feature behavior;
- appropriate framework conventions;
- minimal architecture;
- regression safety;
- scope discipline.

--------------------------------------------------
BE-002 — Validation
--------------------------------------------------

Assess:

- server-side validation;
- schema validation;
- invalid input rejection;
- boundary values;
- unexpected parameters;
- malicious-looking input;
- safe error responses.

--------------------------------------------------
BE-003 — Authorization
--------------------------------------------------

Assess:

- authenticated vs unauthenticated;
- authorized vs unauthorized;
- role enforcement;
- server-side checks;
- no frontend-only control.

--------------------------------------------------
BE-004 — BOLA / IDOR
--------------------------------------------------

Assess:

- object-level authorization;
- cross-user access;
- cross-tenant access where fixture applies;
- direct ID manipulation;
- nested-resource access;
- ownership boundaries.

If BOLA is not applicable to a specific fixture:

mark NOT APPLICABLE.

Do not fake coverage.

--------------------------------------------------
BE-005 — Mass Assignment
--------------------------------------------------

Assess:

- protected fields;
- role/privilege manipulation;
- hidden/internal fields;
- fillable/guarded strategy or project equivalent;
- malicious request payload;
- unchanged protected state.

--------------------------------------------------
BE-006 — Transaction Integrity
--------------------------------------------------

Assess:

- multi-step write behavior;
- rollback on failure;
- partial write prevention;
- integrity after exception;
- duplicate/retry behavior where relevant.

If transaction behavior is genuinely not part of a scenario:

mark NOT APPLICABLE.

--------------------------------------------------
BE-007 — Pagination
--------------------------------------------------

Assess:

- default page size;
- maximum page size;
- invalid page/per_page;
- large page number;
- stable ordering;
- no duplicate/missing traversal where testable;
- data-scope preservation;
- resource limits.

--------------------------------------------------
BE-008 — Query / N+1 Behavior
--------------------------------------------------

Assess:

- query count where practical;
- relationship loading;
- N+1 risk;
- unnecessary query multiplication;
- bounded result set;
- resource abuse potential.

--------------------------------------------------
BE-009 — Negative Security Tests
--------------------------------------------------

Assess relevant negative paths:

- unauthenticated;
- unauthorized;
- invalid input;
- malicious input;
- object-boundary violation;
- protected-field modification;
- excessive resource request;
- replay/duplicate where relevant;
- forbidden method/endpoint behavior.
